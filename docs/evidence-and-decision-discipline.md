# Evidence and decision discipline

Status: design decision (maintainer-ratified) · Scope: cross-cutting rules for
how agents and the controller ground facts, admit irreversible actions, and
record autonomous decisions.

These four rules were adjudicated in an interactive session with the maintainer,
so they are **ratified, not pending** (see rule 3's carve-out). Most are
**recorded for future subsystems and gated**; one — revision-bound artifact
grounding — **applies now**. No implementation is introduced by this document;
it fixes vocabulary and invariants so later work does not re-derive them or
smuggle in the weaker forms.

## Why these exist

They are the durable residue of a design discussion, not a plan for a new
subsystem. The recurring failure they guard against, stated once:

> A signal from a lower layer is not a semantic fact of the upper layer.

Three instances the discussion actually produced, each a case of a convenient
lower-layer signal impersonating a higher-layer truth:

```text
pipeline exit code   ≠  proof of confinement
    (`bash -lc` without pipefail returns 0 even when a piped network op was
     denied — src/gate.rs:166 runs bash -lc; a confinement oracle must assert
     the kernel effect (EPERM/EACCES, zero connections, absent side effect),
     never the gate verdict or a pipeline exit code)

fd number 3          ≠  identity of a capability
    (a closed fd number is reusable by the kernel; capability identity is the
     bound session — cap_grant_nonce + manifest + socket-type check +
     exact survivor-set oracle, per docs/architecture/capability-fd-transport.md)

HTTP 409             ≠  the epistemic status STALE
    (409 is overloaded across authorities; only a *typed* precondition mismatch
     classified by the authority adapter is STALE)
```

Per rule 4, these worked examples are themselves factual claims about existing
code, and they are bound to **this document's own revision** — the natural
revision anchor a versioned file already carries (git records the commit; that
is the binding, not a SHA copied into prose, which would be a fresh unbound
claim in its own right). Line numbers are illustrative and drift; the named
**property**, not the line, is the claim. Each example is stale once its cited
file changes — re-verify against current `HEAD`, and keep the artifact-says /
inference split, before citing any of them as evidence.

The cross-cutting constraint that follows from all three (an implementation
constraint, **not** a fifth rule — it threads through rules 1, 2, and 4):

```text
raw representation / transport signal
        │  authority-specific classifier
        │  (knows the authority's contract, preserves the raw evidence)
        ▼
typed semantic fact
        │  deterministic policy
        ▼
decision or admissible transition
```

The campaign machine and the reducer must never reason directly over shell exit
codes, fd numbers, or HTTP statuses. A classifier that knows the specific
authority and its contract translates the raw result into a closed, typed
semantics first.

## The four rules

### 1. Projection-bound contracts

An agent-visible contract and its runtime enforcement are derived from **one
versioned canonical model**, checked by a shared positive/negative semantic
conformance corpus, and bound by the identity of the **actually-used
projections, generators, and parameters** — not by the shared presumed source
alone.

- `canonical_model_digest` alone never proves which bytes the agent saw or which
  semantics the runtime executed — and this holds **even with a single
  generator** (generator-version skew between prompt-prep and runtime-build,
  a stale cached schema, partial regeneration, changed generation flags, an
  intra-run divergence, or post-generation substitution all break it).
  Multiple generators make the gap obvious; they do not create it.
- Bind, at least: `canonical_model_digest` + version, `agent_projection_digest`
  + its generator identity, `runtime_projection_digest` + its generator
  identity, and projection parameters — or one `contract_bundle_digest`
  canonically computed from those fields.
- "One generator" is a good default (smaller drift surface), not an
  architectural invariant: distinct projections (e.g. a Rust validator and a
  TypeScript SDK) may be generated by different components, provided the four
  tiers hold — Authority (one canonical model + one semantics version),
  Projection (deterministic versioned generators), Conformance (shared corpus),
  Evidence (the digests above).

Disposition: **record for MG-C+** (first real consumer is the model gate's
agent-facing schema vs runtime validator; not built now).

### 2. Atomic precondition consumption

Every irreversible action names an authoritative precondition identity, binds
the decision and evidence to it, refreshes the observation immediately before
acting, and **atomically consumes it via a conditional authority operation**.

```text
1. Name the authoritative precondition identity.
2. Fix the observed identity at decision time.
3. Bind the decision and evidence to that identity.
4. Refresh the observation immediately before the action.
5. Execute the mutation conditionally and atomically against the identity.
6. Record a receipt with the consumed precondition and resulting identity.
```

- Steps 1–4 alone are only a disciplined check-then-act, and TOCTOU eats
  disciplined checks for breakfast. Step 5 is load-bearing.
- For merge, the authority already provides step 5: `PUT /repos/{o}/{r}/pulls/
  {n}/merge` accepts `sha` and returns **409 if the head moved** (verified
  against GitHub's REST docs) — `merge(sha = accepted_head)` is the atomic
  conditional mutation. This is exactly the exact-head admission of
  `docs/decision-and-admission-protocol.md`, generalized.
- Where an authority offers no conditional mutation: lease, transaction,
  compare-and-swap, one-shot grant, or an explicit acknowledgment of an
  unclosed TOCTOU with fail-closed behavior.
- A **typed** precondition mismatch means STALE: invalidate the prior
  adjudication and restart from the observation/decision boundary — **never
  blind-retry the mutation** (a broker that re-fetches head and re-merges on a
  409 reopens the very TOCTOU step 5 closed). Distinguish it from already-applied
  (recover the receipt), policy denial (REFUTED / HUMAN_REQUIRED), and
  operational failure (UNAVAILABLE) — the transport code alone is not the
  classification.

Disposition: **cross-cutting rule** (applies to the future GitHub broker and any
future irreversible action; not built now).

### 3. Non-self-ratifying autonomous decisions

An autonomous architectural decision — one an agent makes *without a human in
the loop* — stays **pending** until a human ratifies or rejects it. A pending
decision is not normative authority and **cannot be cited to justify the next
autonomous decision** (else an agent writes itself permission and then presents
it to itself).

- Register only autonomous decisions crossing a real threshold: a new
  architectural boundary, public API or wire semantics, trust/custody policy,
  normative naming, a change to acceptance meaning, or a new authoritative
  source of truth. **Not** local refactoring, private names, a fix mandated by a
  frozen contract, a decision taken interactively with a human, or a consequence
  of an already-ratified decision.
- Do not inflate the register into a universal hallucination detector — that
  makes it a bureaucratic linter with priestly ambitions.
- Carve-out (demonstrated by this very document): decisions adjudicated in an
  interactive session with the maintainer are already human-agreed, so they are
  ratified, not pending.

Disposition: **governance candidate** (adopt as a lightweight convention, likely
an `docs/adr/` register; not code).

### 4. Revision-bound artifact grounding

A factual claim about existing architecture must be bound to a specific
authoritative artifact and its revision/digest, and must separate what the
artifact *says* from the inference drawn on top of it.

```text
1. Name the authoritative artifact.
2. Name the exact section or machine-checkable property.
3. Bind to the artifact's revision / commit / digest.
4. Distinguish  "artifact says X"  /  "inference Y"  /  "decision Z".
5. Treat the claim as STALE once the governing artifact changes, until re-checked.
```

- This shares rule 2's identity/staleness shape but differs operationally: a
  factual claim **binds** a revision and is invalidated when it changes; it does
  not *atomically consume* one. Structure kin, semantics distinct.
- The worked failure: "an FD cannot be copied" was asserted about an existing
  mechanism and is false — FDs are copied via `dup`/`dup3`/`fork`/`SCM_RIGHTS`,
  which `docs/architecture/capability-fd-transport.md` itself relies on (the
  single-owner invariant closes the sender's copy after each hop). A reference
  to that doc *without a revision* can point at a document that changed tomorrow;
  for a human chat that is usually fine, for an agent about to draw a normative
  conclusion it is not.
- The three-level separation is mandatory, or an inference quietly redresses as
  a citation and a later agent cites the inference as source truth — a mythology
  factory in Markdown:

  ```text
  Artifact says:  SCM_RIGHTS duplicates descriptors.
  Inference:      single ownership therefore requires explicit sender closure.
  Decision:       the protocol mandates close-after-success on every hop.
  ```

Disposition: **strengthen now** — the cheapest rule, applies immediately with no
code: stop accepting claims like "the core already guarantees this" without the
artifact, the revision, and the exact property that establish it.

## Disposition summary

```text
Projection-bound contracts          RECORD FOR MG-C+
Atomic precondition consumption     CROSS-CUTTING RULE
Non-self-ratifying decisions        GOVERNANCE CANDIDATE
Revision-bound artifact grounding   STRENGTHEN NOW
raw→classifier→typed→policy         IMPLEMENTATION CONSTRAINT (through 1, 2, 4)
```

No new code follows from this document. Rules 1–3 are records for subsystems
that do not yet exist (MG-C and a later action broker); rule 4 is a discipline
applicable to every claim made in this repository today.
